# M6 — Complete match and static delivery: verification

**Date:** 2026-10-10 · **Base commit:** `269b380` (M0–M5 review)

## Scope and changed systems

- **Match flow (UI):**
  - Main menu: New skirmish, Continue, Load, Settings, Controls, and a development-scenario launcher.
  - Skirmish setup: faction, map and AI difficulty cards, built from data.
  - Pause menu (P / F10 / top-bar button, or automatically when the tab is hidden): Resume, Save, Load, Settings, Controls, Quit to menu.
  - Results screen: Victory / Defeat / Stalemate with a per-side statistics table, plus View battlefield, Main menu and Play again.
  - All menus are native `<dialog>`s managed by one `DialogStack` (`src/ui/menus.ts`). Esc goes back one level, and gameplay input is ignored while a dialog is open.
  - The scenario and difficulty selectors were removed from the top bar. The top bar now shows a match clock, an audio toggle (M) and a pause button.
- **Objective rule** (`World.updateObjectives`, scenario flag `victory`):
  - Before deploying, a player is kept alive by its deployable unit (MCV). After it owns an objective building, only the HQ counts.
  - Losing your last objective is a defeat. If both sides lose theirs on the same tick, the match is a draw.
  - `world.outcome` freezes `step()`.
  - Sandbox scenarios (`victory` false) never end.
  - Per-player statistics: units/buildings built and lost.
- **Skirmish data:**
  - `data/skirmish.json`: credits, offered maps, default map and faction, and each faction's starting units.
  - `src/sim/skirmish.ts` builds a validated scenario from `MatchSetup {map, faction, difficulty}`.
- **Second map:**
  - `data/maps.json` gains the generation parameters (`generation`) and palette overrides (`palette`). Defaults equal the Lowlands, which generates unchanged.
  - New preset **The Ardennes**: denser forest, a southern river, northern rocks, different roads, farms, spawns and resources, and a winter palette.
  - `tests/helpers.ts validateSkirmishMap` checks that both maps meet these rules:
    - a deploy site within 4 tiles of each spawn;
    - at least 220 buildable tiles within radius 10;
    - at least 2 supply dumps within 30 path tiles;
    - every resource reachable;
    - the two bases connected by ground.
- **Versioned saves** (`src/sim/save.ts`):
  - JSON `{format: "steel-front-save", version: 1, rules: FNV-1a hash of all data files, map checksum, setup, world}`.
  - The world snapshot covers:
    - entities, players (queues, AI state, fog masks run-length encoded, remembered structures in Map order);
    - pending placements and commands;
    - the random state and counters;
    - the projectile pool, including its free list;
    - navigation occupancy, structure arrays and revision.
  - Caches (distance fields, spatial grid, pathfinder scratch) are rebuilt.
  - Loading parses and validates everything (shape templates, type IDs, ranges, cross-references, mask sizes, projectile pool) into a **fresh** World. The running match is never touched by a rejected file.
  - Readable reasons are given for: invalid JSON, not a save, unsupported version, different game data, map mismatch, unknown setup, and bad fields.
  - Size limit: 3,000,000 characters.
  - Three localStorage slots; storage-full errors are reported.
- **Audio** (`src/audio/sfx.ts`):
  - Every effect is synthesized with WebAudio (oscillators plus seeded noise bursts); there are no audio files.
  - The AudioContext is created or resumed inside the first pointer or key gesture (checked against MDN via context7).
  - Up to 14 voices, with a minimum spacing between repeats of each cue.
  - Sound fades with distance from the view, and only visible events are heard. Audio is held while the tab is hidden.
  - Volume, mute and screen-shake preferences are kept in localStorage.
- **Presentation:**
  - Screenshake from nearby heavy explosions and deaths. It is disabled under `prefers-reduced-motion` and can be switched off in Settings.
  - A slow day-light tint from the map palette (20-minute cycle).
  - Effects, markers, selection and terrain renderer are cleared or disposed on every match change.
- **AI tuning (`data/ai.json`, `ai.ts`):**
  - New `minCredits` gate on base-plan steps.
  - Veteran and Regular were retuned so that higher difficulty is stronger (see below).

## Review fixes (R1–R7) and the balance pass

These were done after the M6 checkpoint commit `98a85b3`, in the same session.

They address the seven P2 findings in `M0-M5-review.md`. Each has a regression test in `tests/review.test.ts`, which failed before its fix (checked by reverting the fixed files).

| Finding | Fix | Regression |
|---|---|---|
| R1 artillery dead zone | Attack-move never selects a target inside every weapon's minimum range, and drops one that moves inside. An explicit attack backs off to the middle of the firing band. | Idle, explicit attack and attack-move each fire. The close truck is destroyed (attack) or the far tank is destroyed (idle, attack-move). |
| R2 hidden-structure leak | The placement ghost uses `previewProblem`. Fully visible sites get the live check. Unexplored ground is refused before any live collision check, and fogged tiles use terrain plus *remembered* structures. Tile colours, the move cursor and the move marker follow the same rule. The place command is still validated authoritatively in the simulation. | Identical ghost problem and fills whether or not a hidden distant building exists; unexplored in-range site → `unexplored`. |
| R3 stale route | Harvest, deposit and capture orders stop the previous route; a tile step in progress still completes. | Engineer captures and truck loads after replacing a long move. |
| R4 aircraft move gate | Only a selected *ground* unit can make a move order unreachable; aircraft-only selections over water always move. | Browser: fighter over river tile (52,70), real right-click → `move:47@60,70` enqueued, goal set. |
| R5 production focus | Rebuilding the tabs/cards restores focus to the active tab (or the same card). Clicking a tab claims panel focus. | Browser, real input: click Vehicles → 1 queued a halftrack; W → Infantry, focus kept; 2 queued an MG team; E → Vehicles, focus kept. |
| R6 hostile evacuation | Placement and deployment only move the placing player's own units. Hostile occupants keep their orders and block until placement times out. | Friendly truck makes way and the generator is built; a hostile truck gets no order and blocks the site. |
| R7 AI oil after relocation | The capture filter compares the derrick's approach ring with the base's actual ground region (MCV tile or HQ ring), not the old spawn tile. | Relocated Axis anchor (96,64) captures a derrick and earns oil. |

### Balance pass found while re-running the AI tournament

**Lowlands oil.** The Lowlands gave the east spawn 3 of the 4 derricks under the AI's "closer to own start" rule, so the east won every mirror match (east oil about 18,000 vs about 4,500 credits by 24 minutes).

- Two derricks moved: (74,18) → (48,14) and (60,112) → (82,106). Each side now has two on its half, and mirror-match oil incomes stay within 300 credits.
- With equal economies, mirror matches are decided by near-deterministic combat on each map's terrain. The Lowlands now favours the west (9–0, 3 draws) and the Ardennes the east (12–0). This is recorded as a limitation.

**Difficulty order.** Every level was income-bound and kept about 40 credits in reserve. The faster Veteran planner spent its extra decisions on early waves that died against a defender using its whole army. In the measurement matrix (both maps × both spawns × both factions), Recruit beat both higher levels.

Two data-driven knobs were added to `data/ai.json`, and the rules validate both:

- `incomePercent`: this computer player's deliveries and oil are scaled. Humans always earn 100%.
- `waveCommitPercent`: the share of the army beyond the reserve that a wave commits.

Final values:

| Level | Income | Waves |
|---|---|---|
| Recruit | 75% | unchanged |
| Regular | 100% | unchanged |
| Veteran | 130% | commits 100% of the surplus; start 8, every 3000 ticks, at most 40 |

Waves also draw round-robin across unit types, so they are reliably mixed.

Results over 8 games per pairing:

| Pairing | Before | After |
|---|---|---|
| Veteran vs Recruit (won–lost–drawn) | 2–6–0 | **8–0–0** |
| Veteran vs Regular | 2–6–0 | **8–0–0** |
| Regular vs Recruit | 2–6–0 | **7–1–0** |

`tests/review.test.ts` asserts that Veteran beats Recruit from either spawn and out-earns it.

Pressure on a passive player who only deploys (time to defeat; Recruit / Regular / Veteran):

| Map | Recruit | Regular | Veteran |
|---|---|---|---|
| Lowlands | 14.3 min | 9.6 min | 7.3 min |
| Ardennes | 11.3 min | 11.1 min | 10.1 min |

On the Lowlands, Veteran's first wave launches at tick 6001 with 13 units.

The earlier browser defeat (6:39) and victory (19:18) runs above used the pre-pass tuning. The game data hash changed, so saves from before this pass are rejected as "different game data", by design.

## Known limitations

- Mirror matches are spawn-sided per map (Lowlands west, Ardennes east), even though the economies are now equal. The human always takes the first spawn (west).
- The difficulty gap is partly an explicit AI income modifier (Recruit 75%, Veteran 130%), documented in `data/ai.json` and BALANCE.md.
- Fogged-but-explored building sites are judged on remembered information. If a hidden structure has since appeared there, the place command is rejected with a notice when it executes.
- Winter trees use the generic tree sprites; only the ground palette changes.
- The victory QA used the AI planner to drive the player's side. No fully hand-played 20-minute match was completed.
- Sound output was verified by voice counts and context state, not by ear.
- The production panel keeps its last match's DOM behind the main menu until a new match starts. It is covered by the modal, so it cannot be clicked.
- Sustained frame pacing was observed, not measured over a long session, on a separately defined midrange laptop.
- Caddy is not installed in this workspace. The README Caddy examples (domain root and `handle_path` subdirectory) were not run here. The same subdirectory layout was verified with a plain static file server.
