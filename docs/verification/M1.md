- Rendering: `render/iso-shapes.ts`, `unit-atlas.ts` (procedural 16-direction sheets; turrets separate; infantry walk frames), `entity-layer.ts` (interpolated, depth-merged with scenery), `markers.ts`; `terrain-renderer.ts` takes an optional depth layer.

- `engine/loop.ts`: `advanceFrame` explicitly pauses gameplay while `document.hidden` and discards partial hidden time.

## Design decisions
- **Movement model:** one ground unit per tile (a rifle squad is one entity). A unit holds its current tile and reserves the next one. Moves are 8-neighbour with no diagonal corner cutting. Diagonal steps take 1448/1024 of a straight step, so travel time matches route geometry.
- **Collision rules (data):** water blocks ground units; bridges, roads, meadow, farmland, banks and rocky ground are passable; oaks, pines, boulders, cottages, ruins and towers block; hedges do not.
- **Congestion:** a blocked unit waits for movers. It shoves idle units, and on head-on contact (or a long jam) it shoves the lower-priority unit. Priority = waiting-time aging, then id. The shoved unit follows a BFS route to the nearest free tile outside the requester's next 24 waypoints. It may pass through other stationary units, which are shoved in turn, so a column backs off a one-tile bridge. Units blocked for 40 ticks re-route around stationary units within 8 tiles. After 160 ticks without progress, an occupied destination is reassigned to the nearest unclaimed free tile. Interrupted orders resume after yielding. Units shoved off a finished slot stay where they land.
- **Formation:** distinct slots in BFS order from the resolved target, preferring open tiles (≥6 passable neighbours) so units do not fill dead-end forest pockets. Each unit is greedily matched to its compressed relative offset. If there are fewer legal slots than units, the extra units are marked `no-room` and are reassigned by the no-progress rule.
- **Path jobs:** FIFO and atomic. Each job runs to completion, and jobs start only while the 30,000-expansion tick budget remains, so no search is ever half-finished at a tick boundary (important for M6 saves). The A* heuristic is `max(octile, field[n] − field[goal])`, using a Dijkstra distance field toward the command target. This is admissible, and the test asserts optimal cost. Fields are memoized by `target:gridRevision` and are a pure cache, not state.
- **Determinism:** fixed-point positions (1024 per tile), integer path costs, byte angles via an arithmetic-only atan approximation, stable id ordering, no wall clock or `Math.random` in `src/sim/`.
- Stop is bound to **X** (S is camera pan). Ctrl+digit stores groups (Cmd+digit is left to the browser on macOS).

## Browser check

Actions performed with real pointer and keyboard events:

- Click selected a single Stuart. Shift-click added a rifle squad and Shift-click toggled the tank off. Shift-click on the same type within 350 ms counts as a Shift-double-click and adds that type.

Sprite sheets were inspected at 3.4× magnification. Bug fixed during QA: insignia decal radii were applied in tile units, which filled entire frames; they now use pixels.

## Performance
The built-in browser pane was hidden while testing, so Chrome throttled `requestAnimationFrame` to about 1 FPS. **Real 60 Hz frame intervals could not be measured in this environment.**

As a substitute, `steelFront.benchmark(600)` renders 600 frames synchronously while panning, with one sim tick every third frame. On the 200-unit stress scenario (87 visible) it measured application CPU work of median **0.2 ms**, p95 **0.8 ms**, max 37.8 ms per frame. The max is a single warm-up/GC outlier. Simulation median was 0.1 ms per tick, max 7.2 ms (the command's distance field plus the first 30k-expansion path batch). This excludes GPU raster and compositing time.

## Known issues / not performed
- 60 Hz frame-interval sampling on a visible window was not performed (hidden pane); repeat with the pane visible or in a normal browser.
- Crossing the map with 200 units through two one-tile bridges takes about 7 minutes of game time. That is correct but slow; bridges are the intended chokepoint.
- Mid-step orders finish the current tile step (≤1 s) before turning.
- Pointer cancellation was covered by code paths (`pointercancel`, `lostpointercapture`, `blur`) but not exercised with a touch device.

1. `npm ci && npm test && npm run build`
2. `npm run dev` and open the URL. Drag over the force, right-click across the river (the north bridge is at tile row 59, the south at row 92). Use Ctrl+1 / 1, double-click, Shift-click and X.
3. Click **STRESS 200**, then select all and right-click east. In the console, `steelFront.benchmark(600)` prints CPU frame cost.
